## 🎯 Цель проекта

- **Какую задачу решает приложение:** В традиционном обучении математике учащиеся механически подставляют числа в формулы и пассивно вычисляют результат. Приложение «Пойми ответ» меняет этот процесс на противоположный: учащимся даётся готовый график или результат, и они должны восстановить исходные параметры/условия с помощью интерактивных инструментов.
- **Почему эта задача важна:** Развивает активную математическую интуицию, пространственное мышление, критический анализ и проверку гипотез вместо механического заучивания.
- **Целевая аудитория:** Школьники (средние и старшие классы), учителя математики, репетиторы и самообучающиеся, практикующие координатную геометрию и алгебру.

## 📌 Требования к приложению

### Функциональные требования
- Многотемный математический тренажёр («Точка в системе координат», «Линейная функция», «Квадратичная функция / Парабола»).
- Интерактивная графическая отрисовка на кастомных View (`CoordinatePlaneView`, `LinearFunctionView`, `ParabolaFunctionView`).
- Интерактивные инструменты-подсказки (перетаскивание точек-подсказок, сдвиг параллельных прямых, построение прямых по двум точкам, ось симметрии, точки на графике).
- Механизм защиты от хитрости (радиус запретной зоны $R \le 2.0$, предотвращающий наведение подсказок прямо на цель).
- Парсер математических выражений в реальном времени (`MathExpressionEvaluator`), позволяющий вводить арифметические выражения во все поля.
- Полноценная двуязычная локализация (английский / русский) с мгновенным переключением и сохранением выбора в `SharedPreferences` (по умолчанию English при первом старте).
- Контекстные диалоговые окна справок и пошаговых математических решений.

### Нефункциональные требования
- **Производительность:** Плавная отрисовка Canvas на 60 FPS, предварительное выделение объектов Paint/Path, отсутствие блокировки UI-потока.
- **Удобство использования:** Интуитивный интерфейс Material 3, крупные зоны захвата пальцем, адаптивная верстка под разные экраны.
- **Надёжность:** Строгая валидация ввода, защита от вылетов при неверном синтаксисе или делении на ноль.

## 🧠 Общая архитектура

- **Выбранный подход:** Компонентно-модульная архитектура View-Fragment (модель MVC / Hybrid View-Driven Pattern).
- **Почему выбран именно он:** Идеально соответствует жизненному циклу Android View, обеспечивая низкие накладные расходы, прямую работу с Canvas и переиспользуемое управление экранами на базе Fragment.
- **Основные компоненты системы:**
  - `StartActivity`: Стартовый экран с логотипом, описанием, переключателем языка и кнопкой старта.
  - `TopicSelectionActivity`: Экран выбора темы на базе MaterialCard.
  - `MainActivity`: Главный контейнер `FragmentContainerView` и верхней панели с диалогами справки.
  - `CoordinatePointFragment`, `LinearFunctionFragment`, `ParabolaFunctionFragment`: Обработчики логики уроков.
  - `CoordinatePlaneView`, `LinearFunctionView`, `ParabolaFunctionView`: Производительные кастомные View для Canvas-графики.
  - `MathExpressionEvaluator`: Рекурсивный парсер арифметических выражений.
  - `LanguageManager`: Менеджер локалей и сохранения настроек.

## 🧩 Подробное описание классов

### 📌 Класс: MainActivity
- **Роль:** Главная активность-контейнер для фрагментов тем и верхней панели.
- **Ответственность:** Принимает Intent-параметры из `TopicSelectionActivity`, загружает соответствующий Fragment и обрабатывает кнопку помощи в тулбаре.
- **Основные методы:**
  - `onCreate(Bundle savedInstanceState)` — инициализация макета, настройка EdgeToEdge, тулбара и загрузка первого фрагмента.
  - `showHelpDialog()` — отображает модальное окно MaterialAlertDialog с правилами в HTML-формате.

### 📌 Класс: StartActivity
- **Роль:** Стартовый экран приложения.
- **Ответственность:** Отображение логотипа, названия, описания методики, группы переключения языка (English / Русский) и кнопки «Начать».

### 📌 Класс: TopicSelectionActivity
- **Роль:** Экран выбора тем.
- **Ответственность:** Отображение доступных тем в карточках MaterialCardView и запуск `MainActivity` с выбранным ID темы.

### 📌 Класс: CoordinatePointFragment / LinearFunctionFragment / ParabolaFunctionFragment
- **Роль:** Контроллеры математических разделов.
- **Ответственность:** Генерация случайных задач, привязка кастомных View, проверка ответов, вычисление пошаговых решений и обратная связь.

### 📌 Класс: CoordinatePlaneView / LinearFunctionView / ParabolaFunctionView
- **Роль:** Кастомные графические компоненты Canvas.
- **Ответственность:** Отрисовка координатной сетки $[-15..+15]$, осей, стрелок, подписей, графиков функций, интерактивных подсказок и зон защиты от хитрости.

### 📌 Класс: MathExpressionEvaluator
- **Роль:** Модуль вычисления математических выражений.
- **Ответственность:** Разбор и безопасное вычисление арифметических выражений (например, `(7 - 3) / (4 - 2)`).

### 📌 Класс: LanguageManager
- **Роль:** Менеджер языковых настроек.
- **Ответственность:** Сохранение выбранного языка в `SharedPreferences` (по умолчанию `"en"`) и применение локали через `AppCompatDelegate`.

## 🔄 Сценарий работы приложения

1. Запуск приложения -> `StartActivity` загружает сохранённый язык (при первом старте — English).
2. Пользователь выбирает язык по желанию -> Интерфейс меняется на лету.
3. Нажатие «Start» / «Начать» -> Открывается `TopicSelectionActivity`.
4. Выбор темы -> Открывается `MainActivity` с нужным фрагментом (например, `ParabolaFunctionFragment`).
5. Генерация случайных математических условий.
6. Взаимодействие с графиком (перетаскивание подсказок, сдвиг параллельных прямых, поиск оси симметрии или открытие точек).
7. Защита от хитрости блокирует приближение подсказок к цели ($R \le 2.0$).
8. Ввод выражений в поля ответа -> Вычислитель проверяет ответ -> Пользователь получает мгновенный отзыв и подробные диалоги с решением.

## 🎨 UI/UX анализ

- **Философия дизайна:** Чистый Material 3 дизайн.
- **Использованные принципы:**
  - *Простота:* Лаконичный главный экран, громоздкие тексты вынесены в диалоги справки.
  - *Логичность:* Иерархия сверху вниз (График -> Переключатели/Инструменты -> Поля ввода -> Действия).
  - *Доступность:* Крупные зоны для касания пальцем ($28\text{dp}+$), контрастная сетка, всплывающие `Toast`-уведомления.

---

## ⚙️ Работа с потоками

- **Модель потоков:** Основной поток Android (Main/UI Thread) для отрисовки View и обновления UI.
- **Оптимизация производительности:** В кастомных View предотвращается выделение памяти в `onDraw()` (все Paint и Path создаются в `init()`).
- **Предотвращение ANR и утечек памяти:** Использование короткоживущих контекстов, исключение статических ссылок на View, управление `Runnable` через `removeCallbacks()`.

---

## 💾 Работа с данными

- **Хранение:** `SharedPreferences` (`app_language_prefs`).
- **Сохраняемые данные:** Код выбранного языка (`"en"` или `"ru"`).
- **Надёжность:** Асинхронная запись `apply()` гарантирует сохранение без задержек UI.

- **Область применения:** Приложение работает полностью оффлайн. Сетевые запросы не требуются.

## 🧪 Тестирование

- **Подход к тестированию:**
  - Автоматическая компиляция Gradle и анализ кода (`analyze_file`).

## 🐞 Обработка ошибок

- **Предусмотренные сценарии:**
  - Неверный синтаксис -> Предупреждающий Toast и текстовая методика.
  - Деление на ноль -> Перехват `ArithmeticException` с сообщением «Деление на ноль».
  - Пустой ввод -> Напоминание ввести все коэффициенты.
  - Нарушение зоны защиты -> Вспышка красной предупреждающей зоны и Toast.
